### 방안 B: 서비스 통합 (3-Tier → 2-Tier)

**개선 내용:**
기능적 유사성에 따라 5개 → 2-3개 서비스로 통합

```
AS-IS (5 services)              TO-BE (2-3 services)
┌─────────────────────┐         ┌─────────────────────┐
│ auth-service (3011) │         │ core-service (3011) │
│ admin-service(3012) │   →     │  - auth             │
│ common-service(3015)│         │  - admin            │
└─────────────────────┘         │  - common           │
┌─────────────────────┐         └─────────────────────┘
│ content-service(3013)│        ┌─────────────────────┐
│ communication(3014) │   →     │ app-service (3012)  │
└─────────────────────┘         │  - content          │
                                │  - communication    │
                                └─────────────────────┘
```

| 장점 | 단점 |
|------|------|
| 리소스 절약 (메모리, DB 커넥션) | 코드 리팩토링 필요 |
| 배포/관리 단순화 | 서비스 단위 스케일링 유연성 감소 |
| 서비스 간 통신 불필요 | 마이그레이션 리스크 |
| 빌드 시간 단축 | 장애 범위 확대 가능 |
