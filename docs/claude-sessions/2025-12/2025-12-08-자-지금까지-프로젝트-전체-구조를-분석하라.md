- SSO 연동

**API 예시:**
```

POST /auth/verify-mfa
POST /auth/refresh
POST /auth/logout
```

### 📊 데이터베이스 분리 전략

#### Phase 1: 논리적 분리 (스키마 분리)
```sql
-- 단일 PostgreSQL, 스키마로 분리
CREATE SCHEMA auth_schema;    -- Auth Service
CREATE SCHEMA admin_schema;   -- Admin Service  
CREATE SCHEMA content_schema; -- Content Service
CREATE SCHEMA comm_schema;    -- Communication Service
CREATE SCHEMA common_schema;  -- Common Service
```

#### Phase 2: 물리적 분리 (향후)
```
Auth Service     → PostgreSQL (auth_db)
Admin Service    → PostgreSQL (admin_db)
Content Service  → PostgreSQL (content_db) + Redis (캐시)
Comm Service     → PostgreSQL (comm_db) + Redis (큐)
Common Service   → PostgreSQL (common_db) + S3 (파일)
```

### 💡 핵심 권장사항

1. **5개 서비스가 최적** - 너무 작게 나누면 운영 오버헤드 증가
2. **Auth 먼저 분리** - 보안상 가장 중요하고 경계가 명확
3. **스키마 분리부터 시작** - 물리적 DB 분리는 나중에
4. **API Gateway 필수** - 라우팅, 인증, Rate Limit 통합
5. **공유 라이브러리** - 타입, 유틸은 별도 패키지로 관리

```typescript
// src/lib/axios/index.ts

const isDevelopment = process.env.NODE_ENV === 'development';

// 환경별 API URL 매핑
const API_CONFIG = {
  development: {
    // 로컬: 각 서비스 직접 호출
    auth: 'http://localhost:3011',
    admin: 'http://localhost:3012',
    content: 'http://localhost:3013',
    comm: 'http://localhost:3014',
    common: 'http://localhost:3015',
    legacy: 'http://localhost:3001/api',  // 마이그레이션 전
  },
  production: {
    // 서버: API Gateway 경유
    auth: '/auth',
    admin: '/admin',
    content: '/content',
    comm: '/comm',
    common: '/common',
    legacy: '/api',
  }
};

const config = isDevelopment ? API_CONFIG.development : API_CONFIG.production;

// 서비스별 클라이언트
export const authApi = axios.create({ baseURL: config.auth });
export const adminApi = axios.create({ baseURL: config.admin });
export const contentApi = axios.create({ baseURL: config.content });
export const commApi = axios.create({ baseURL: config.comm });
export const commonApi = axios.create({ baseURL: config.common });
export const legacyApi = axios.create({ baseURL: config.legacy });

// 또는 단일 클라이언트 + 동적 baseURL
export const api = axios.create({
  baseURL: isDevelopment 
    ? 'http://localhost:3001/api'  // 마이그레이션 전: Legacy
    : '',                           // 서버: 상대 경로 (Nginx가 처리)
});
```

```env
PORT=3011
NODE_ENV=development

# Database (원격 DB)

DB_USER=corenext

# Redis (비활성화 - In-Memory 사용)
```

```
[auth-service] Redis disabled, using in-memory storage
[auth-service] Auth Service started on port 3011
```

## 원인

`package.json`에서 `@enterprise/shared`가 `file:../../shared`로 로컬 경로 참조되어 있는데, Docker 빌드 시:
1. `npm install`이 `file:../../shared` 경로를 찾으려 함
2. Docker 컨텍스트에서는 `/app/service`가 작업 디렉토리이므로 `../../shared` 경로가 존재하지 않음

## 해결

```dockerfile
# npm install 후 shared 패키지 심볼릭 링크 생성
RUN npm install --ignore-scripts && \
    rm -rf node_modules/@enterprise/shared && \
    mkdir -p node_modules/@enterprise && \
    ln -s /app/shared node_modules/@enterprise/shared
```

서버에서 다시 빌드:

```bash
git pull
docker compose build auth-service
```
